# AgentEval 0.6 产品闭环与验收

> 历史交付记录。当前工作台范围、异常类型、复测身份与发布问题匹配以 [0.7 契约](V0.7_SCOPE_ACCEPTANCE.md)为准；当前产品演示使用同 Agent 的修复版本，不再以跨 Agent 复测关闭问题。

**定位：** 面向 Agent 开发团队的自动化质量评测与回归决策平台。

本轮围绕“新版本是否更好、哪里退化、证据是什么、是否具备发布条件”组织现有评测核心。产品闭环：接入 → 评测 → 诊断 → 修复 → 回归 → 发布建议。发布建议不执行部署。

## 1. 质量工作台

首页从资源数量概览改为质量工作台。通过 GET `/api/v1/quality/workbench/{project_id}` 获取当前项目的真实数据，不从资源列表的当前页推算总数。

- 通过率、Trial 评分证据覆盖、P95 来自同一候选固定批次；有版本比较时展示其候选，否则展示最近已完成批次。
- 变化值以固定比较的基线为准。无比较时不显示虚构增减，不能把单次通过解释为版本可发布。
- 待处理缺陷只统计已导入跟踪的问题，并明确这一口径；未导入的所有 Bad Case 不会冒充已管理缺陷。
- 优先队列由数据库按阻断级排序，覆盖全部项目记录，避免遗漏当前资源页之外的问题。
- 最近保存的发布评估明确标注为历史快照，不因后续修复自动改写。

## 2. 三步评测向导

入口“开始评测”，无项目时可直接创建项目，无需先逐项建立底层资源。

1. 连接 Agent：选择部署好的 Python/LangGraph 插件或允许清单中的 HTTP 地址，声明观测通道。插件检查只确认注册；HTTP 检查发送 HEAD 并报告服务响应，不发送业务执行 POST，不把声明当作已实测能力。
2. 选择目标：回答、工具、轨迹、RAG 或独立状态验证。缺少声明能力时相应目标不可选；状态验证必须选择部署环境。由已有评分器生成 Profile，不增加评分机制。
3. 导入 JSON/JSONL 与标签，执行正常 Run。预检失败定位 case_key / evaluator；不猜测预期结果。数据、Agent 和评分版本、Run 与请求回执在同一事务提交，失败回滚；同一请求键相同配置返回同一 Run，不同配置拒绝。

向导以新接入资源为单位，已有 Agent 的后续版本仍可在资源管理中发布。基础执行、能力预检、预算、Trace、评分和固定批次机制全部复用。模型密钥不进入向导。

## 3. Bad Case 生命周期

从任务页“跟踪本批次异常”或 Bad Case 页导入固定评分批次。相同批次与执行重复导入复用已有问题。旧引擎批次需先重新评分后再导入，避免建立无法按当前引擎兼容复测的问题。

状态：open（待确认）→ confirmed（已确认）→ fix_in_progress（修复中）→ ready_for_retest（待复测）→ resolved（复测通过）。可退回修复；关闭后可重新打开。一般更新接口不能直接设置 resolved。

证据包含执行状态、评分依据、独立环境快照、Trace 与来源。类别由确定性规则产生；例如最终输出规则通过而独立状态失败，展示“输出与业务状态不一致”。排查建议标注候选解释，开发者确认的根因在独立字段保存。历史尝试中的硬约束失败仍作为历史事实展示，不因 canonical 尝试成功而丢失阻断级依据。

每次处理记录、复测开始、复测核验及回归沉淀都保存 IssueEvent。revision 乐观锁防止覆盖并发更新。负责人和说明属于当前可信团队的人工记录，不冒充已认证的个人身份；本轮没有引入 RBAC。

复测可以选择修复后的 Agent 版本，沿用原测试集与 Profile。只有新批次已完成、同项目、输入与断言一致、评分/执行/环境/Judge/引擎策略兼容，并且所有对应重复 Trial 均通过，才设为 resolved；未通过回到修复中。修改标签不能直接作为修复。旧引擎产生的问题不自动按新引擎认定修复，需先在当前引擎重新建立可比证据。

“加入长期回归集”为项目维护一个普通 Benchmark 的不可变版本。保留原始输入与断言；新案例创建新版本，同一内容复用已有版本。case_key 冲突但内容不同使用哈希后缀区分，不改写原测试集，也不自动调整核心用例门禁。

## 4. 三态发布决策

从固定版本比较或“发布决策”生成 ReleaseDecision：

| 状态 | 条件 |
|---|---|
| 可发布 ready | 严格且兼容的比较、质量门禁通过、两侧判定与 Trial 评分覆盖均为 100%、候选无更新评分批次、无同候选用例范围的开放阻断问题 |
| 阻断 blocked | 兼容严格比较中确定门禁失败，或仍有同候选输入/断言范围的开放阻断问题 |
| 证据不足 insufficient | 旧引擎证据、探索或不兼容条件、样本/观测不足、覆盖不完整、候选有更新评分批次等 |

开放阻断问题需要兼容复测确认关闭，即使某个新候选的独立比较门禁已通过，也不会悄悄代替缺陷确认流程。发布建议仅覆盖所选测试集、Profile、版本及批次；输出规则方案不会被包装成已独立验证业务状态。

保存时冻结比较、版本名称、问题 ID/修订号、原因、覆盖率和说明。后续重评或问题关闭不改写历史结论，应生成新比较/新评估。JSON/HTML 导出绑定决策 ID，带内容哈希，HTML 转义用户内容，均需鉴权。发布评估页不直接触发生产发布。

## 5. API 与持久化

| 功能 | 入口 |
|---|---|
| 向导配置 / 接入检查 | GET `/onboarding/options`；POST `/onboarding/check` |
| 一次建立评测闭环 | POST `/onboarding/evaluations` |
| 项目完整比较选择 | GET `/quality/runs`、`/quality/comparisons`，支持分页，不受资源工作台当前页限制 |
| 异常导入 / 列表 / 证据 | POST `/quality/issues/import`；GET `/quality/issues`、`/quality/issues/{id}` |
| 确认与修复记录 | POST `/quality/issues/{id}/update` |
| 发起 / 核验复测 | POST `/quality/issues/{id}/evaluations`、`/quality/issues/{id}/retest` |
| 沉淀回归集 | POST `/quality/issues/{id}/regression-case` |
| 发布评估 / 列表 / 固定详情 | POST/GET `/release-decisions`；GET `/release-decisions/{id}` |
| 发布报告 | GET `/release-decisions/{id}/export?format=json|html` |

路径均带 `/api/v1` 前缀。0006 新增 quality_issues、issue_events、regression_collections、release_decisions、onboarding_receipts；迁移使用固定 DDL，旧执行和评分不回写。

## 6. 演示、验证与升级

`python scripts/product_smoke.py` 使用独立临时数据库，以公开 API 验证假报成功、阻断、确认、修复、LangGraph 复测、回归版本及三态发布报告。`examples/product_demo.py` 提供可复用演示函数；预览项目为“AgentEval 0.6 产品闭环演示”。数据来自本地集成样例，不是用户生产 Agent 的效果数据。

浏览器覆盖三步向导、异常跟踪、修复状态、实际复测、回归沉淀、发布报告下载及移动端。后端覆盖事务回滚/幂等、非法跳转、并发修订、改标签拒绝、历史硬约束、开放阻断、更新批次、快照不回写与导出转义。CI 除 SQLite 外，在 PostgreSQL 上执行产品 smoke，同时保留真实 Redis/Worker 协议检查。

升级：停止旧 API/Worker/Dispatcher，备份数据库，运行 `python -m agenteval init-db` 至 0006，重新构建前端并启动服务。预览升级保留历史数据。

首次有效评测 ≤15 分钟、首次接入成功率 ≥80%、Bad Case 可定位率 ≥90%、核心复测成功率 ≥95% 是待真实试用建立基线的目标，不是本轮已经测得的成果。两个真实业务 Agent、独立人工标签与实际 Judge 校准、生产安全和长期运维仍待后续验收。本轮没有增加自动业务标签、LLM 自动根因断言、Prompt/代码自修改或新 Agent 框架。
