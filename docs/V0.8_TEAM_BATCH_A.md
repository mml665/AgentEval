## 2. 后端与 API 契约

不新增数据库表或列，仍为迁移 0007。新增字段为向后兼容的读取元数据；既有运行、GradingBatch、Comparison.report、Issue.evidence 和 ReleaseDecision.snapshot 不重写。

### 任务查询

GET `/api/v1/evaluations` 保留 project_id、offset、limit，新增：

| 参数 | 语义 |
|---|---|
| q | 最多 200 字，任务 ID / Agent 名 / Benchmark 名包含搜索；百分号和下划线按字面处理 |
| status | queued/running/evaluating/cancelling/completed/cancelled/failed |
| quality | pending/passed/failed/insufficient；基于最新 revision 固定批次摘要，不从执行状态推断 |
| version | Agent 版本标签精确匹配，最多 120 字 |
| created_after / created_before | ISO 日期时间，含边界；无时区按 UTC，有时区换算 UTC；倒置返回 422 INVALID_TIME_RANGE |
| sort | newest/oldest，创建时间方向加 ID 稳定次级排序 |

列表返回 items/total/offset/limit；项目筛选仍遵循当前共享 Token 管理契约，**不是新增项目权限证明**。身份授权将由批次 B 统一加入。窗口函数选择每个任务最高 revision，按批次聚合判定与最终执行评分，按页批量查询，避免逐任务 N+1。

`quality_summary` 包括 grading_batch_id、revision、grading_status、quality_status、counts、planned_trials、unassessed_trials、trial_scoring_coverage、updated_at、duration_ms、duration_scope、initiator。

质量语义：批次未完成/不存在时 pending；已完成且确定失败优先 failed；仅计划试验大于零、全部通过且最终执行应评分项全部有有效评分时 passed；其余 insufficient。用例判定为 unknown 且原因列表为空时，详情明确显示“证据未形成有效判定”，不会使用通过兜底文案。质量摘要不是发布建议，不替代基线比较及发布门禁。执行完成不等于质量通过。

duration_ms 为已记录所有尝试的调用耗时之和，不冒充墙钟耗时。updated_at 为该批次判定记录时间，无判定时为批次创建时间；并非精确评分完成时间。历史和当前共享 Token 均未关联真实个人，initiator 明确标为 unattributed_team，不用自由文本负责人伪造操作者。

GET `/evaluations/{id}` 返回同一最新批次摘要。GET `/evaluations/{id}/report?grading_batch_id=...` 返回指定批次摘要，切换批次数量和结论一致。

### 指标与比较

报告 latency_ms 追加 min_samples、sufficient、scope、excluded_trials，阈值来自该批次 grading_manifest.gate.min_latency_samples，缺失时由后端使用既有门禁默认策略。仅 canonical completed 执行且有耗时的样本参与 P95，失败/未完成及历史重试不参与。样本不足显示“样本不足”，可查看仅供参考的观测值；历史已存比较未带阈值时显示待核对，不在前端补默认 20。没有业务场景分母，不生成业务覆盖率。

比较详情、工作台、workspace 和项目比较查询追加 context，批量关联两侧不可变版本、运行与批次。该元数据与原 report 分开，既有快照不被补写。原始 GET `/regressions` 管理列表保持旧格式；控制台使用增强的 workspace 和 quality/comparisons。

### 证据摘要

GET `/executions/{id}/evidence-summary?grading_batch_id=...` 要求明确评分批次，并验证执行和批次属于同一任务；不匹配返回 404 BATCH_NOT_IN_RUN。返回 headline、items、execution_id、grading_batch_id、trace_id 和适用说明。

摘要只使用对应规则结果；最终输出与参考断言确实一致且 exact_match 有对应证明，才表述答案通过。匹配其他自定义字段、通过 JSON Schema、缺失状态证据或历史不同尝试不能冒充最终答案/业务状态成功。未知、评分异常、执行超时保留不确定性，不用候选解释当根因。

差异按 JSON Pointer 路径展示，保留“字段缺失”与 null、布尔与数字的区别，最多 20 项、递归深度 12。原始评分、哈希、状态快照和 Trace 继续可展开查看。摘要 API 是现有可信团队的展示能力，不等同于 AE-003 的统一脱敏或原始证据权限已交付。

SDK 示例：

```python
with AgentEvalClient(base_url, machine_or_existing_deployment_token) as client:
    page = client.list_evaluations(project_id, q="订单", quality="failed", version="2.0", limit=10, offset=0)
    task = page["items"][0]
    fixed = task["quality_summary"]["grading_batch_id"]
    report = client.get(f"evaluations/{task['id']}/report", grading_batch_id=fixed)
    execution = report["trials"][0]["execution_id"]
    facts = client.get(f"executions/{execution}/evidence-summary", grading_batch_id=fixed)
```

新机器身份尚未实现，当前 SDK 仍使用部署 Token；示例令牌变量不代表已经具备机器权限范围。现有 get/post/wait 调用保持兼容。
