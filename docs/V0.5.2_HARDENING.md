# 0.5.2 证据与恢复边界修复

沿用用户要求：不增加 UI 或评分器种类，真实业务 Agent 和实际 Judge 校准等待资源。

- 工具故障序号改为调用入口分配，使用 Recorder 内锁保护，记录 call_index；不再用已完成调用数推断序号。并发调用逆序完成及递归同名工具均不会复用故障目标。序号表达本次执行实际进入顺序，不保证跨运行调度顺序；跨运行对齐仍应使用稳定 call_id。
- OTel instrumentation scope 使用当前引擎版本，去掉固定 0.4.0 标记。
- 环境状态评分检查来源及状态内容 SHA-256 一致性；损坏或非平台独立来源为 evaluator_error，不得产生状态通过/失败分数。哈希仅检查内容一致性，不代替权限控制或来源认证；来源信任边界仍是平台控制的 Execution 字段。
- 增加 reset_unconfirmed 指标；环境观察失败、重置未确认或未知效果保留现场时，质量门禁为 inconclusive，原因 ENVIRONMENT_RESET_UNCONFIRMED。已确认的硬约束失败仍按既有失败优先规则处理。
- 严格回归比较包含 Profile.environment 配置；不兼容时 API 返回 409，探索比较披露 environment 差异，不生成通过结论。
- 真实进程崩溃测试增加“重置实际完成、完成标记尚未提交”场景：现场已清空，但数据库仍保留重置前终态及 pending 标记。测试按准确执行命名空间核验，不错误推断其他并发用例也已重置；恢复继续保留 outcome_unknown，不把 pending 猜成 verified。

验证方式：pytest 全量、现有 5 项浏览器测试、HTTP/状态与 RAG/队列进程 smoke。0.5.1 的 Compose 全链路实测记录继续保留；本轮未将旧容器测试冒充 0.5.2 镜像重新部署验收。没有新增数据库迁移，仍使用 0005；升级前备份数据库并重启 API/Worker/Dispatcher。

2026-11-03 验证：100 项 Python 测试、5 项真实浏览器测试、前端生产构建，以及 HTTP、独立状态/RAG、独立队列重启和 Worker 崩溃 smoke 全部通过。本地 8010 预览已备份并更新至 0.5.2。
