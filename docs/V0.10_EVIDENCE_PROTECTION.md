# 0.10：证据展示保护与非破坏性归档

日期：2026-11-05。对应 AE-003。交付版本化脱敏视图、个人原文专项权限、留存提醒/引用观测、签名项目快照和隔离空库恢复。仍是受控内部试用版，不代表任意业务秘密都可自动识别，也不代表当前 Compose 发布包已完成全部灾备验收。

## 1. 原始证据与派生视图

输入、输出、规则事实、环境快照、Trace、错误、工作项、Issue、审计备注和发布报告的业务 JSON 响应默认应用同一脱敏引擎。数据库中原始 JSON、Manifest/状态来源哈希、评分和发布快照不改写；评分器仍读取原始证据。脱敏只改变展示，不把缺失字段猜测成通过，也不重新计算历史评分。

默认规则遮蔽敏感字段名、普通文本中的邮箱、Bearer、常见 password/api_key/secret 赋值及 URL 用户名密码。支持嵌套 JSON、列表、OTel 字符串化 JSON、文本和已配置秘密的 URL/JSON/HTML 常见编码。字段名本身出现邮箱或已配置秘密时也遮蔽。不是任意编码、语言或业务 PII 分类器，未知格式须配置路径或部署内容引用并补充项目测试。

项目管理员在“团队与凭据 → 证据保护与留存”发布不可覆盖的新策略；并发修订冲突返回 409。字段路径为 JSON Pointer，`*` 匹配一层，`**` 匹配任意层，例如 `/**/customer/phone`。路径针对返回 JSON 结构，不应遮蔽运行 ID、状态或 UI 必需的协议字段。没有项目策略时应用默认规则。

内容规则只登记 `AGENTEVAL_REDACTION_SECRET_` 前缀的部署环境变量名，不接收秘密值；额外环境名须显式映射进 Compose API。登记使用 0.9 的 `AGENTEVAL_CREDENTIAL_FINGERPRINT_KEY` 计算不可变版本指纹。变量未配置时不能发布；发布后变量消失/原值变化时普通业务视图返回 503，防止悄悄失去遮蔽。管理员仍可访问策略管理接口恢复配置或发布新版本。轮换时保留历史敏感值的部署引用，确认旧证据得到保护后再变更规则，不能把只匹配新值当成已覆盖历史秘密。

实际 API：

```http
GET /api/v1/protection/policy/{project_id}
POST /api/v1/protection/policy/{project_id}
```

```json
{"expected_revision":0,"paths":["/**/customer/phone"],"secret_env_names":["AGENTEVAL_REDACTION_SECRET_CUSTOMER"],"redact_emails":true,"retention_days":30}
```

所有业务 JSON 默认走展示边界；导出在渲染前使用相同策略，CSV 公式处理和 HTML 转义保留。业务 API 头部 `X-AgentEval-View: redacted`、`X-AgentEval-Policy` 标识策略，`X-AgentEval-View-Hash` 是实际返回字节的 SHA-256。报告内部 `view` 标识策略版本及完整性范围，`content_hash` 对应派生导出内容。保留的 `manifest_hash` 等仍只适用于原始存储数据，不能用脱敏 JSON 重新验证原始哈希。

SDK `get/post` 返回同样的默认视图，机器 Token 不能请求原文。沿用 `client.get(f'evaluations/{run_id}/report', grading_batch_id=batch_id)`，无需在客户端另写脱敏规则。低层 HTTP 客户端可读取上述响应头检查派生摘要。

安全会话、机器令牌一次性签发和身份/凭据管理元数据保留必要协议字段；管理审计的业务备注不在此例外中。原文仅通过下一节的授权入口返回，`?raw=true` 不能绕过展示保护。单次 API 展示缓冲上限 16 MiB，超过时拒绝返回，使用分页证据接口；这不是流式大文件导出实现。

默认 CLI 启动关闭含 URL 查询值的 Uvicorn access log；API 意外异常仅记录异常类型和路由模板，不记录原始异常消息。SQLAlchemy 异常隐藏绑定参数，Worker 给 Celery 的异常只含分类代码。操作轨迹由结构化审计保存。部署方另设的反向代理、数据库、采集器和第三方 Agent 日志不受此 Python 边界控制，必须另行配置保密和访问规则。

## 2. 个人原文权限与审计

默认包括管理员在内的普通读取仍显示脱敏视图。只有个人部署管理员或具有同项目 `raw_read` 专项授权的有效个人成员，才能提交原文读取请求。viewer 的原文权限独立于业务写权限。机器令牌及共享 legacy Token 均不能读取原文。

```http
GET /api/v1/protection/grants/{project_id}
POST /api/v1/protection/grants/{project_id}
```

管理员提交 `{"user_id":"<member-id>","raw_read":true}`，撤销时使用 false；只能授权有效项目成员。普通成员只能查询自己的授权。撤销、移出项目、禁用用户或会话失效后，新读取请求被拒绝；不能撤回已经披露到客户端的数据。

```http
POST /api/v1/protection/evaluations/{run_id}/raw
```

请求为 `{"reason":"受控环境检查原始输入与状态证据"}`，理由至少 8 个非空字符。浏览器 Cookie 调用继续要求 Origin/CSRF，跨项目返回 404。返回 Run、用例、批次、Trial、Execution、评分及 Span 原文，`view.content_hash` 只对本次 evidence 包计算。读取前持久化审计意图，记录个人 ID、项目、运行、理由及请求审计关联；审计记录表示获准披露意图，不证明客户端实际接收成功。

评测详情提供“受审计的原始证据”入口，只对有资格的个人显示；填写理由后主动读取，关闭后清除组件内存，登出/切换身份卸载原文。原始数据不进入浏览器持久存储。原始读取权限不能替代部署数据库、文件系统和备份的访问控制。

## 3. 留存与容量观测

策略 `retention_days` 可空，不假定统一业务期限。`GET /protection/storage/{project_id}` 返回运行数、超期数、被发布快照引用的运行数及超期发布引用数。另提供 response + Trace 序列化 JSON 字符数，明确不是物理磁盘字节，也不代表所有证据表总容量。

没有自动删除、截断或清理动作；留存期只作为治理提醒。Issue、比较、评分和发布引用均随项目快照保留。归档不移动或删除原库，不能因为到期、已归档或存在较新评测就清理固定报告依据。细粒度制品生命周期、加密对象存储、在线冷热迁移和容量上限告警仍待后续部署需求确认。

## 4. 签名项目快照与隔离恢复

部署侧 CLI 需要独立 `AGENTEVAL_ARCHIVE_SIGNING_KEY`（至少 32 个随机字符），由 Secret 管理并单独备份。不会自动修改现有 `.env`、生成或打印此密钥。签名是 HMAC-SHA256，**不是加密**；快照含原始业务证据，必须放在只允许部署运维访问的路径，不能上传公开 CI 工件或 Git。POSIX 新文件以 0600 创建；Windows 由部署方配置目录 ACL，代码不声称 0600 等同于 Windows 权限隔离。

先停止该项目的写入和消费，确认运行及评分已稳定；CLI 以一致性事务读取。存在在途运行、评分或可投递工作项时拒绝归档。保留 blocked 未知结果及其原始语义，不重发未知副作用。项目快照包含版本、测试用例、固定运行/批次、证据/Span、Issue/适用范围/事件、比较、发布快照、预算、凭据引用、保护策略和单项目操作审计。归档完整性清单记录表计数、项目身份、引擎/迁移版本、内容摘要、理由及签名。

```powershell
$env:PYTHONPATH = 'backend'
# DATABASE_URL 指向源库；ARCHIVE_SIGNING_KEY 由部署环境提供。
.venv/Scripts/python.exe -m agenteval archive-project --project-id '<项目ID>' --archive-file 'data/protected-archives/project.json' --reason '隔离恢复验收与证据留存'
.venv/Scripts/python.exe -m agenteval verify-archive --archive-file 'data/protected-archives/project.json'
```

文件独占创建，不覆盖原归档或备份。校验拒绝签名/内容/结构不一致及超过 256 MiB 的单项目快照；此版本不适用于大规模制品归档。签名密钥遗失会使校验失败；原库仍保留，因此不以归档成功作为删除原库的依据。

恢复目标必须是**独立、已迁移到 0009、没有业务数据的数据库**，先验证目标绝对地址，停止目标 API/Worker/Dispatcher，再显式确认隔离恢复：

```powershell
# 仅独立空库；不要把此地址设成现有预览或生产库。
$env:AGENTEVAL_DATABASE_URL = 'sqlite:///./data/isolated-restore.db'
.venv/Scripts/python.exe -m agenteval init-db
.venv/Scripts/python.exe -m agenteval restore-archive --archive-file 'data/protected-archives/project.json' --confirm-isolated
```

恢复先校验签名，使用同一事务导入并验证回读内容和外键；非空业务库、ID/唯一约束冲突及内容不一致均拒绝，不执行覆盖、合并、删除。日期列为跨数据库校验归一化，JSON 内证据和业务哈希保持原文。归档、校验和恢复另记录部署 CLI 审计。

不导入账户、项目成员、会话、机器令牌、原文授权或服务心跳；历史 actor 的身份快照和审计 ID 保留，不能自动变成当前权限。恢复后由部署方重新配置成员及原文资格。秘密值、外部状态环境目录、第三方服务和队列 Broker 不包含在项目快照；凭据/内容规则的环境引用与原部署指纹密钥须另行配置。此工具验证项目证据恢复，不是整站密码/队列/环境及当前 Compose 灾备备份。

## 5. 升级与验证

先停止旧进程、确认无在途调用并备份数据库，运行 `python -m agenteval init-db` 至 **0009**，前后端同步更新到 0.10。新表为策略版本和原文授权，历史证据不回写。默认脱敏立即应用于历史页面；需要原文时按个人授权入口读取。旧 Token 兼容模式继续可用，但不能读原文。旧数据回退应恢复配套发布包和备份，不在现有证据表执行破坏性演练。

验证包括敏感字段/文本/URL/字符串化 JSON、路径规则、未配置及轮换时拒绝返回、导出摘要、原文授权/理由/跨项目/撤销/机器拒绝、签名篡改、禁止覆盖/非空恢复和固定发布快照恢复。浏览器补充策略发布、默认视图不含测试秘密、个人显式读原文及关闭清除。测试和截图仅使用明确的假秘密。

`scripts/protection_smoke.py` 通过公开 API 创建固定发布证据，核对 JSON/HTML 脱敏与派生哈希，再生成签名项目归档、恢复到隔离 SQLite 并核对原文仍在。CI 的 PostgreSQL 作业也运行此脚本，覆盖实际 PostgreSQL → SQLite 项目恢复；`team_smoke.py` 额外验证 PostgreSQL 原文授权及即时撤销。
