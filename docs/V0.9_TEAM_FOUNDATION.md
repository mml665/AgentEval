# 0.9 团队基础：身份、项目授权与 HTTP 凭据

日期：2026-11-04。交付范围：批次 B 的 AE-001 接入机制、AE-002，以及 AE-003 的插件环境最小化。仍为受控内部试用版；真实业务接入、完整脱敏/原始证据专项授权/归档恢复和当前 Compose 发布包恢复尚未验收。

## 1. 权限与身份契约

| 身份 | 读取 | 写入 | 管理能力 |
|---|---|---|---|
| 部署管理员 | 所有项目 | 所有项目 | 用户、项目、成员、凭据、机器令牌、运维及审计 |
| evaluator | 授权项目 | 授权项目的评测、资源、问题及发布建议 | 无部署管理权限 |
| viewer | 授权项目，包含 Trace 和报告导出 | 禁止 | 仅管理自己的会话 |
| 机器 read/evaluate | 项目白名单 | read 禁止；evaluate 同项目评测成员 | 不能管理成员、凭据或机器令牌 |
| legacy_team | 所有项目 | 所有项目 | 历史共享管理员兼容模式，无个人身份 |

统一依赖从任务、评分批次、执行、Trace、版本、Issue、比较双侧和发布快照反查项目，同时检查 URL、查询及请求体中的引用。跨项目 ID 返回 404，只读写操作返回 403；新增未分类路由默认拒绝非管理员。列表必须受项目范围约束，不能只在界面隐藏操作。`GET /projects` 自动限制到授权项目；其他项目列表传 `project_id`。

Issue 使用 `assignee_user_id` 分配有效项目成员，`owner` 为显示名快照，`legacy_owner` 保留旧自由文本。批量分配与单条更新使用同一校验，任务发起人、人工 Issue 事件和发布建议记录实际 Principal。自动发现的异常没有伪造人工操作者。历史 actor 为空时明确显示共享团队身份/未记录个人，不从 owner 推断。

`security_audits` 在写操作获准时记录请求，响应补记状态和白名单资源标识；未完成响应保留空状态，不冒充成功。Issue/Run/发布 actor 的 `audit_id` 可关联请求审计。管理动作、机器调用、登录、退出及拒绝请求均可追溯；不记录任意请求体、密码、Cookie 或机器明文令牌。`GET /team/audit` 仅管理员可读。人工释放未知占用仍另外要求 `X-Admin-Token` 和理由。

## 2. 开启个人账户模式

本地命令不自动加载 `.env`，`start-local.ps1` 仅为旧兼容模式读取其中的 API Token。以下环境须在启动 API 的同一终端配置，数据库地址必须与待升级服务一致：

```powershell
$env:PYTHONPATH = 'backend'
$env:AGENTEVAL_AUTH_MODE = 'team'
$env:AGENTEVAL_LEGACY_TOKEN_ENABLED = '0'
# 仅本机 HTTP 开发允许关闭 Secure；团队部署使用 HTTPS 和 Secure=1。
$env:AGENTEVAL_SESSION_COOKIE_SECURE = '0'
$env:AGENTEVAL_SESSION_ORIGINS = 'http://127.0.0.1:8010'
.venv/Scripts/python.exe -m agenteval init-db
.venv/Scripts/python.exe -m agenteval init-admin --username admin --display-name '部署管理员'
# 按提示输入并再次确认至少 12 字符的独立密码，不会回显。
powershell -ExecutionPolicy Bypass -File scripts/start-local.ps1 -Port 8010
```

初始化只允许数据库中尚无任何用户时执行，公开 HTTP 接口不能创建首位管理员。受控无人值守部署可短暂提供 `AGENTEVAL_BOOTSTRAP_PASSWORD`，执行后立即移除该变量；不要把密码写入命令参数、仓库、日志或聊天。管理员登录“团队与凭据”后创建成员、分配项目角色；密码重置 API 为 `POST /team/users/{user_id}/password`，会撤销该成员所有会话，当前界面仅提供创建/停用和项目分配。最后一位有效管理员不能被停用。

浏览器使用随机不透明会话；数据库保存摘要、撤销状态、闲置和绝对期限。默认闲置 1 小时、绝对 12 小时，登录不能自动无限续期。HTTPS Cookie 为 `__Host-agenteval`，HttpOnly、Secure、SameSite=Strict、Path=/。写请求同时校验精确 Origin 和 `X-CSRF-Token`。CSRF 值只存前端内存，长期部署 Token 不进入 localStorage/sessionStorage。刷新恢复个人会话；退出、撤销、禁用或密码重置使后续请求失效。

`GET /api/v1/auth/options`、`POST /auth/login`、`GET /auth/session`、`POST /auth/logout` 为会话入口；登录/退出同样要求 Origin，退出另需 CSRF。`GET /auth/sessions` 和 `POST /auth/sessions/{id}/revoke` 管理自己的会话。登录错误按持久化账户/IP窗口限流，默认 5 分钟每账户 10 次、每 IP 60 次，未知账户执行等量密码散列计算。

团队部署必须设置 `AGENTEVAL_SESSION_COOKIE_SECURE=1`、精确 HTTPS `AGENTEVAL_SESSION_ORIGINS`；默认忽略代理头。只有可信反向代理才可配置 `AGENTEVAL_TRUSTED_PROXY_IPS` 的源 IP/CIDR，并由部署网络限制直连。Origin 是外部浏览器地址，代理信任配置不能替代网络隔离。本机 HTTP 配置只允许 localhost/127.0.0.1/::1。

密码使用独立随机盐的 scrypt（N=2^14、r=8、p=5）。参数参考 [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)，会话设计参考 [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。这些实现和测试不代表第三方安全认证。

## 3. 旧 Token 与 SDK/CI 迁移

默认 `AGENTEVAL_AUTH_MODE=legacy` 保留原部署兼容，界面明确显示共享管理员提示。切换 `team` 后，旧 Token 默认无效；确需短期双通道时显式 `AGENTEVAL_LEGACY_TOKEN_ENABLED=1`，其权限仍是部署管理员，不能分配给普通项目成员。迁移完成设为 0 并轮换/移除旧部署 Token。兼容模式退出只清除浏览器内存，不能全局撤销部署秘密。

管理员 `POST /team/machines` 创建限定项目、`read`/`evaluate`、5 分钟至 30 天的机器令牌（默认一天），只返回一次明文；`GET /team/machines` 不返回摘要或明文，`POST /team/machines/{id}/revoke` 立即撤销。机器调用继续使用 Bearer，不需要浏览器 Cookie 或 CSRF；显式无效 Bearer 不回退到 Cookie。UI 可为当前项目签发令牌，API 可显式列出多个授权项目。

```python
import os
from sdk.client import AgentEvalClient

with AgentEvalClient(os.environ['AGENTEVAL_BASE_URL'], os.environ['AGENTEVAL_MACHINE_TOKEN']) as client:
    page = client.list_evaluations(project_id, quality='failed', limit=10)
    # 使用已存在且同项目的不可变版本；SDK get/post/wait 协议不变。
    run = client.post('evaluations', {
        'agent_version_id': agent_version_id,
        'benchmark_version_id': benchmark_version_id,
        'profile_version_id': profile_version_id,
    })
```

Worker/Dispatcher 访问内部数据库和队列，不依赖浏览器登录或机器 Token；不能将机器 Token 误当成 Worker 启动凭据。API、Worker、Dispatcher 必须运行相同版本和部署配置。

## 4. HTTP 凭据引用与验证

部署方在 API/Worker 环境设置实际秘密，例如 `AGENTEVAL_AGENT_SECRET_HTTP_MAIN`，以及不少于 32 字符随机 `AGENTEVAL_CREDENTIAL_FINGERPRINT_KEY`。登记接口只接收变量名，前缀强制为 `AGENTEVAL_AGENT_SECRET_`，不能读取任意平台环境。Bearer 和指定 Header API Key 均可；不接受内联秘密、Cookie、Host、代理或 Trace 控制 Header。UI 不接收/回显值，凭据列表不返回环境名和指纹。

管理员请求示例（以下均是公开协议字段，值不含秘密）：

```json
POST /api/v1/team/credentials
{"project_id":"<project-id>","name":"orders-v1","env_name":"AGENTEVAL_AGENT_SECRET_HTTP_MAIN","auth_mode":"bearer"}
```

从响应取 `id`，在 HTTP AgentVersion 或三步向导的 configuration 中使用：

```json
{"endpoint":"https://test-agent.example/invoke","credential_version_id":"<credential-version-id>"}
```

注册和新评测都校验同项目、存在、未撤销及环境值指纹。Manifest 固定引用；指纹使用部署密钥的 HMAC，不保存明文。不改变已登记凭据版本的值：轮换时增加新环境变量、新凭据版本及新 AgentVersion，所有执行服务更新配置并重启后再切换；旧版本撤销后新调用拒绝，已发出的远端请求不能撤回。旧运行重评使用原证据，不重发 HTTP，也不恢复旧凭据。相同幂等请求仍返回已创建运行。

“HTTP 接入验证”分别提供 HEAD 连接检查与显式测试调用。选择 Agent/用例本身只读取资源；HEAD 405 表示未验证 POST 协议。实际测试须选择固定 Benchmark 用例并确认测试环境，超时上限 30 秒；会调用业务端点，有副作用的用例必须由项目方保证隔离。测试不创建正式 Run、不评分、不作为发布证据。状态区分网络、鉴权、协议和声明的观测，缺少内部观测不能解释为业务失败。

`POST /onboarding/test-call` 的字段为 `agent_version_id`、`benchmark_version_id`、`case_id`、`confirm_test_environment: true`、可选 `timeout_seconds`。401/403、连接/超时、重定向、非法 JSON、缺少 output 和 Agent 业务失败有独立错误码与恢复动作。超时保留远端结果未知。HTTP 返回值/Trace 若直接或经已覆盖编码回显当前请求凭据，整份响应在持久化前拒绝为 `HTTP_SENSITIVE_RESPONSE_REJECTED`；不修改证据冒充原始哈希。这不是任意业务秘密的全面脱敏机制。

仍沿用准确 host:port 允许清单、禁止重定向和禁用环境代理；DNS/IP 固定验证与基础设施出站隔离仍待部署补充。

## 5. 插件环境与数据边界

Python/LangGraph 子进程只继承所需 OS/Python/区域/证书变量、平台注册组件地址及 HTTP 允许清单。API、Admin、数据库、Redis、Judge、HTTP Agent 秘密及初始化密码不传给插件。Windows 保留 SYSTEMROOT 等启动必需变量，真实 LangGraph 子进程已有回归覆盖。

可信插件额外依赖可通过 `AGENTEVAL_PLUGIN_ENV_ALLOWLIST` 显式提供非 `AGENTEVAL_` 名称；部署方必须审核这些变量，仅允许该插件需要的值。此机制是部署级清单，尚无每插件项目秘密代理，不能把全局敏感变量放进清单。插件仍是部署注册的可信代码，不是不可信代码沙箱。

业务文本、嵌套 Trace/URL/错误的统一版本化脱敏、原始读取专项权限、制品留存/引用保留和归档恢复未完成。当前项目内有读权限者仍能读到同项目原始证据；只使用脱敏测试数据。AE-003 仅部分完成，不能因具备个人角色就宣称全部数据保护要求已满足。
