# AgentEval 0.13 证据容量与留存

日期 2026-11-06。对应 AE-003 的容量观测与留存核查。

项目成员在「团队与凭据 → 证据保护与留存 → 容量、期限与报告引用」查看分项容量、超期记录与发布引用。面板展开时开始查询。列表按运行创建时间和 ID 稳定分页，可从记录打开原评测。

部署管理员可在保护策略设置留存天数和证据容量提醒阈值。容量达到阈值时，页面显示提醒。发布快照引用的运行会单独标记，包括已超期的运行。归档继续由部署侧 CLI 执行，保留原始证据及固定快照。

## 接口

- `GET /api/v1/protection/storage/{project_id}` 返回现有运行数、引用数、超期数及响应与 Trace 字符数。新字段 `evidence_json_bytes` 汇总 `evidence_json_bytes_by_kind` 四类数据库 JSON 文本的字节数，分别是执行响应、Trace、独立状态快照和评分结果。部署磁盘容量需另按数据库及卷统计。
- `GET /api/v1/protection/storage/{project_id}/runs` 支持 `review=overdue|referenced`、`offset` 和 `limit`。默认每页 25 条，最多 100 条。只返回本项目运行 ID、创建时间、执行状态、超期及引用标记。
- 策略增加可选整数 `evidence_warning_bytes`，有效范围为 `1` 至 `2^50`，`null` 清除。旧客户端省略字段时继承上一修订的阈值。阈值与脱敏和留存规则一起受策略修订校验。达到阈值由 `warning_reached` 表达。
- PostgreSQL 和 SQLite 都在数据库内聚合。引用统计按项目与运行 ID 去重。超期以运行创建时间和当前 UTC 时间计算。
- 迁移头仍为 `0010`，阈值随策略 JSON 持久化并参加项目归档恢复。旧策略缺少字段时视为未设置。历史报告可照常读取，新发布建议遵循现有引擎版本校验。

## 验证

Windows 工作区可用以下命令复现容量测量。传入正的 `--inventory-runs` 时，脚本使用新建临时 SQLite 库。

```powershell
.venv/Scripts/python.exe scripts/protection_smoke.py --inventory-runs 5000
```

隔离夹具添加 5,000 条超期运行，每条有一个执行响应和一条 Trace 记录。一次本机测量中，证据 JSON 共 5,370,183 字节，摘要响应为 770 字节。五次请求耗时中位数 85.69 毫秒、最大 86.28 毫秒，末页记录和发布引用计数校验通过。报告保存在 `.build/protection-smoke.json`。

SQLite 回归覆盖多字节 JSON、重复发布引用、超期分页、权限和旧策略客户端。浏览器覆盖保存阈值、展示提醒及跳转原运行。PostgreSQL CI 使用同一项目保护和归档 smoke 校验 SQL 方言差异。生产数据量、并发与恢复目标继续按试点要求验收。
