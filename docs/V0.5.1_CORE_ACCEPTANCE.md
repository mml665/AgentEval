## 崩溃与来源语义

快照提交后 reset 前崩溃，reset_status 保留 pending；reset 后完成标记提交前崩溃，也保守保留 pending，不推测重置是否成功。租约恢复保留采集的状态与响应，同时执行结果仍可为 outcome_unknown；独立状态满足不自动把不确定执行改为 passed。快照提交前崩溃或数据库无法提交时，环境保留，不能保证进程内尚未落盘的观测幸存，也不声称已持久化。

来源由平台写入 Execution.evidence_provenance，不信任 Agent 返回的同名字段。来源描述表达采集方式，不代表对业务规则或 Agent 自述真实性的背书。注入配置进入 Manifest，并在执行证据标为 platform_profile，避免模拟结果混作正常生产工具结果。

## 故障注入配置

Profile.execution.tool_faults 示例：

```json
[{"tool_name":"get_order","call_index":1,"mode":"mock","mock_output":{"status":"processing"}},
 {"tool_name":"get_order","call_index":2,"mode":"timeout","delay_seconds":2}]
```

call_index 是同名工具调用序号；每个目标只能指定一个规则。timeout 注入在工具边界抛 TimeoutError；delay_seconds 超过 Agent 整体超时可验证进程超时路径。仅受控埋点入口能注入，是否触发可检查 tool.fault_injection 事件。当前同步示例适用，未声称支持任意并行第三方工具的稳定序号映射。

升级需备份数据库并运行 init-db 至 0005，重启 API/Worker/Dispatcher。核心验证：pytest、HTTP smoke、独立状态/RAG smoke、独立队列 smoke。真实接入和模型校准待资源提供后继续。
