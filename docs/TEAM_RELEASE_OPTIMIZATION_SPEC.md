# AgentEval 团队可用版优化需求与开发交付说明

文档版本：1.0  
日期：2026-11-04  
评估基线：AgentEval 0.7.0  
状态：按批次实施中；0.8～0.11 交付日常操作、团队身份、证据保护与产品流程。0.12 增加 AE-004 当前包独立部署/故障/全库与环境恢复/兼容回滚工具和证据，见 [0.12 运维交付](V0.12_OPERATIONS.md)。真实业务、Judge 校准、容量及用户效率继续待验，不能视为全文正式上线验收完成。
面向人员：前端、后端、测试、运维、产品及试点业务负责人。

## 1. 目标与范围

将现有版本优化为可信内网环境中可日常使用的团队评测平台，使用户能独立完成“接入 Agent → 准备用例 → 执行评测 → 定位失败 → 修复复测 → 形成发布建议”。

默认首发范围为内部团队、可信部署插件和受控业务测试环境。公网多租户商业化、不可信代码沙箱、计费系统及大量第三方连接器不在本轮范围。开发可立即开展不依赖真实业务资源的任务；缺少业务接口、标签或模型资源时，相关验收应保留待验状态。

现有固定资源版本、历史评分批次、证据追溯、未知结果保留、兼容复测及三态发布判断必须保留。不得为了界面简化而覆盖历史记录、跳过兼容性校验、将未知当作通过，或把发布建议等同于执行部署。

本需求基于本机页面审查和代码阅读，不是新的全量测试报告。真实业务、Judge、压力和灾备验收未在本次审查中完成。

## 2. 优先级与交付顺序

P0 为团队正式上线条件；P1 为本轮产品化交付范围；P2 为试点后候选需求。交付批次与优先级不同，P1 快速修复可与 P0 基础建设并行。

| 批次 | 交付任务 | 主要负责方 | 完成标志 |
|---|---|---|---|
| A：日常操作修正 | AE-101～103、AE-106、AE-108、AE-201 | 前端、后端、测试 | 任务结论、搜索、指标、证据、比较对象可以直接辨认 |
| B：团队基础 | AE-001～003 | 后端、前端、运维、测试 | 真实鉴权接入、项目权限、会话和数据保护具备验收证据 |
| C：流程收尾 | AE-104～105、AE-107、AE-109～111 | 前端、后端、测试 | 复用评测、用例维护、异常处理与发布上下文贯通 |
| D：上线验收 | AE-004、全量受影响流程回归 | 测试、运维、业务、产品 | 当前发布包通过业务闭环、恢复及可用性验收 |

开发拆分每个任务时补充负责人、依赖、预计工作量和验收证据。安全会话和权限方案先形成简短设计，明确旧 API/SDK 的兼容方式再实现；不要求等待全部任务设计完成后才启动批次 A。

## 3. P0 开发与上线任务

### AE-001：带鉴权的真实 HTTP Agent 接入

现状依据：`backend/agenteval/adapters.py` 只允许 endpoint 配置，HTTP 调用未提供可配置的 Agent 鉴权头；向导 HEAD 检查不等于协议执行成功。

开发要求：

- 支持无鉴权、Bearer 和指定 Header 的 API Key 方式；配置中保存服务端凭据引用，不保存明文密钥。
- 凭据仅由有权限的管理员配置，界面不回显原值；冻结运行所用的凭据引用及版本标识，明确撤销后的重跑行为。
- 将检查结果区分为地址校验、网络可达、鉴权、协议和观测能力；未实际验证的步骤显示“未验证”。HEAD 返回 405 不直接推断业务 POST 不可用。
- 提供独立的测试调用动作，使用明确选择的测试用例；对有副作用任务明确提示测试环境要求。不能在填写地址或切换选项时自动执行业务调用。
- 区分连接失败、401/403、超时、协议结构错误、缺失观测和 Agent 业务失败，提供对应恢复动作。

验收：真实鉴权 HTTP Agent 能执行评测；凭据失效、权限不足、超时和无效 JSON 均有可理解反馈；运行、Trace、错误日志和导出无测试明文密钥；重定向及出站允许清单原有约束仍有效。新增接口或字段须同步 API/SDK 使用示例。

### AE-002：团队身份、项目权限与会话

现状依据：`backend/agenteval/api.py` 使用部署共享 Token；`frontend/src/App.tsx` 仅在内存保留登录状态；负责人为自由文本。

开发要求：至少支持部署管理员、项目评测成员、项目只读成员；服务端按项目授权，不能只隐藏前端按钮。成员具备稳定身份，问题分配从成员列表选择，关键操作记录实际操作者。

| 操作 | 管理员 | 评测成员（授权项目） | 只读成员（授权项目） |
|---|---|---|---|
| 查看资源、结果和脱敏报告 | 允许 | 允许 | 允许 |
| 创建评测、维护用例、处理问题、生成发布建议 | 允许 | 允许 | 禁止 |
| 管理成员、凭据、项目策略 | 允许 | 禁止 | 禁止 |
| 人工释放未知占用等高风险运维动作 | 专项管理权限及理由 | 禁止 | 禁止 |

- 会话需可过期、可撤销；刷新后恢复登录及当前项目/页面；不得将长期团队 Token 直接写入 localStorage。
- 机器调用保留明确的认证方式并限定权限；旧部署 Token 的迁移、撤销和管理员初始化需提供操作说明。
- 历史无个人身份的记录标为“历史团队身份/未知”，不能伪造操作者。退出后清理相关缓存与页面数据。

验收：直接调用 API 同样不能越权；项目 A 的成员不能凭任务、Trace、报告 ID 读取项目 B 数据；只读者不能执行写操作；退出、过期、撤销有效；负责人和审计可关联到真实成员。

### AE-003：数据保护、插件边界与留存

现状依据：`backend/agenteval/exports.py` 主要按固定字段名脱敏；可信插件进程继承父进程环境。已有机制不是不可信代码沙箱。

开发要求：

- 保持可信插件准入边界；对子进程环境使用明确的必需变量集合，兼顾既有 Python/LangGraph 插件运行依赖。
- 对输入、输出、Trace、错误、日志和导出统一制定字段路径及内容脱敏规则；保留必要的诊断上下文。
- 明确原始证据的存储权限和脱敏展示关系，不能在脱敏时悄悄破坏已有哈希、来源验证或历史可复现性。
- 提供可配置的留存策略、容量观测和归档流程；有发布快照引用的证据先明确保留规则，避免自动清理导致报告失去依据。

验收：嵌套字段、普通字符串、URL/错误消息中的测试敏感值不出现在未授权展示与导出中；插件不收到无关平台凭据；归档、恢复后固定报告引用可核对。留存期限由部署方配置，不在代码中假定统一业务期限。

### AE-004：真实业务与当前发布包验收

这是开发、业务、测试和运维共同任务，不能只由前端完成。

- 选定两个真实业务 Agent，覆盖 HTTP 和 Python/LangGraph 中一种方式；至少一个场景具备独立状态验证。业务方提供测试环境、参考标签和预设失败案例。
- 每个 Agent 完成失败发现、问题确认、修复版本、兼容复测、回归沉淀和发布评估。正常、边界、故障、高风险案例分别有结果记录。
- 如 Judge 参与正式门禁，冻结模型、提示词、人工标签集和验收阈值，检验一致性及重复波动。未校准能力只能保留试验标识，不单独承担放行职责。
- 使用本次交付的发布包验收部署、数据库迁移、备份恢复、队列和运行中进程故障，以及可执行的回滚方案。破坏性演练在隔离验收环境执行。

验收：预设严重缺陷均被发现，未知和缺失证据不被放行；恢复后任务、批次及快照可核对；报告记录 commit、构建版本、部署模式、数据规模、步骤、结果和遗留问题。业务资源缺失时明确标为未验收，不得以演示样例替代。

## 4. P1 功能与体验任务

### AE-101：任务列表区分执行和质量结论

入口：评测任务列表及详情。参考：`frontend/src/Pages.tsx`、`Details.tsx`。

要求：执行状态和质量结论分列。任务显示已完成，不代表质量通过；展示通过/失败/待判定数、耗时、发起人和结果更新时间。失败数量可直接进入失败结果列表。质量结论由服务端固定批次摘要提供，不由前端根据运行状态猜测。

验收：执行完成但有失败用例时，同时看到“执行完成”和“不通过”；评分未结束、全部未知及部分覆盖不能展示全通过；历史批次切换后数字和结论一致。新操作字段缺失的历史数据展示占位语义。

### AE-102：跨页搜索和筛选

现状：`RunsPage` 对当前页数组过滤。

要求：搜索、筛选和排序在服务端执行，范围限定当前授权项目。支持任务 ID、Agent、Benchmark 搜索，以及版本、时间、执行状态、质量结论筛选。分页总数基于过滤结果；改变筛选回到首页，排序使用稳定次级键；查询状态写入 URL，不包含凭据。

验收：构造超过一页的数据，位于最后一页的目标可从第一页搜索到；清除筛选正确恢复列表；无结果、请求失败、加载中分别展示；连续快速搜索不会被旧响应覆盖；返回列表保留筛选。

### AE-103：指标口径和样本量表达

参考：`Product.tsx`、`QualityMetrics.tsx`、`backend/agenteval/metrics.py`。

要求：通过率展示已通过数、已判定数和计划数，未知/排除单列；把现有“证据覆盖率”准确标为评分或判定覆盖，不等同业务覆盖。P95 展示样本数、样本范围及不足提示；最小样本阈值由后端策略统一返回并与门禁策略协调，前端不另写一套。

验收：单样本不呈现为稳定性能结论；分母为零、全未知、部分判定有明确空值或提示；仅成功调用的延迟指标说明排除失败调用；未定义场景分母时不显示虚假的业务覆盖百分比。

### AE-104：新接入与复用评测双入口

参考：`GuidedEvaluation.tsx`、`Forms.tsx`、后端 onboarding/评测创建逻辑。

要求：开始评测提供“接入新 Agent”和“评测已有版本”；已有版本路径直接选择固定 Agent、Benchmark 和评分方案。支持从历史运行复制配置，提交前显示版本、用例数、重复次数、并发、超时及预计 Judge 调用量。新增接入允许明确版本名；复用操作不重复注册资源。

验收：可直接复用配置运行下一次回归；复制后生成新的运行身份，原运行保持不变；同一提交重试不重复建任务；参数改变不能误复用旧幂等键；不兼容配置在执行前定位到具体字段。

### AE-105：用例表格、校验与版本差异

参考：`Pages.tsx`、`Forms.tsx`、`GuidedEvaluation.tsx`、Benchmark 接口。

要求：保留 JSON/JSONL 为高级方式，增加表格预览和基础编辑，显示 case_key、输入摘要、断言、标签和校验状态。嵌套输入/断言使用结构化编辑或单条详情，不要求强行摊平成表格。导入预检定位行/用例/字段，检查重复键、缺失断言及目标兼容性。支持版本新增/删除/修改差异，修改发布为新版本。

验收：有效复杂 JSON 无信息丢失；错误记录可定位修复，失败导入不产生半套资源；执行前可核对有效用例数；发布后的旧数据集不可被编辑覆盖。CSV/Excel、任意格式映射不作为本轮硬性范围。

### AE-106：证据事实摘要与差异视图

要求：失败详情首屏展示失败规则、事实摘要、预期/实际差异和 Trace 定位入口。按失败、缺失证据、通过组织证据，原始 JSON 和哈希保留为可展开高级内容。优先根据结构化规则生成确定性摘要，不强制引入 LLM。

验收：退款反例明确显示“答案符合预期，但独立状态未出现预期退款记录”；证据不足时显示缺失事实，不能写成已确定业务失败；候选解释与已确认根因分开；摘要引用对应执行和固定批次。

### AE-107：异常管理工作区重排

参考：`Product.tsx` 的 IssuesPage、IssueDetail。

要求：首屏优先展示“待确认、待修复、待复测”计数、筛选和问题列表；异常收集模式移入项目设置；手动导入保留次级入口；选中后出现批量操作栏。详情先展示当前状态、失败事实、负责人和下一步动作，适用范围编辑降为次级区域。提供权限内“分配给我”筛选，依赖 AE-002。

验收：1366×768 首屏能看到问题列表或真实空态；批量处理说明目标数量和不兼容原因；切换范围清空旧选择；并发更新冲突有恢复反馈；复测仍需兼容证据才能关闭，不能手动绕过。

### AE-108：比较对象和发布记录可辨认

参考：`Pages.tsx`、`Product.tsx`。

要求：比较列表展示 Agent、基线版本、候选版本、Benchmark 版本、运行时间/评分批次及严格/探索模式；CMP ID 降为辅助信息。发布比较选择器包含可区分的版本与短 ID，不能只有相同百分比和时间。长名称允许换行或截断并提供完整查看。

验收：两条同一时间、同一成功率的记录仍可区分；打开详情后对象与列表一致；不同 Agent 的探索比较不能误显示为同 Agent 发布建议。

### AE-109：显式基线与可恢复范围

参考：`EvaluationScope.tsx`、`scope_api.py`。

要求：维护按 Agent/Benchmark 适用范围设置的显式基线；没有配置时提示选择，不能将运行排序推导的版本称为“已发布基线”。支持基线/候选交换，确认比较方向；项目、版本、数据集及选定批次通过可分享 URL 恢复。评测详情到问题/比较入口应携带其上下文。

验收：旧版本后运行不会自动替换显式基线；无访问权限或资源失效时明确提示，不能静默落到另一项目；刷新、前进后退、重新登录后恢复有效范围；不得允许不兼容组合通过严格比较。

### AE-110：发布建议边界和时效

要求：保留 ready/blocked/insufficient 后端三态，面向用户表达为“当前评测范围满足门禁/阻断发布/证据不足”。首屏同时展示样本数、范围、未覆盖能力、阈值、基线/候选、固定批次和评估时间。历史快照与当前有效性提示分离；新评分或新适用阻断项出现时提示重新评估，不改写旧报告。

验收：旧报告仍能还原生成时依据；新证据不被悄悄混入旧快照；界面及导出表达一致；满足门禁不表示已部署或已完成生产审批；样本不足原因能定位到对应指标。

### AE-111：草稿与失败恢复

要求：向导支持草稿恢复和未保存离开提示，恢复最近项目和筛选；凭据及可能敏感的用例正文不能未经设计直接持久化到浏览器，优先使用授权的服务端草稿。请求失败保留输入并提供重试；提交结果未知时先查询原请求结果再决定重试。

验收：离开返回或会话恢复后可继续配置；草稿按成员/项目隔离；登出或换用户不泄露前一用户内容；网络重试不产生重复运行。依赖 AE-002 的身份与会话边界。

## 5. AE-201：视觉和交互规范（P1）

保留现有品牌、深色控制台方向和主要组件，不做整体重建。统一调整 `styles.css`、`ui.tsx` 及受影响页面，避免各页新增互相冲突的样式。

| 项目 | 开发要求 | 验收方式 |
|---|---|---|
| 导航 | 分为评测与诊断、资源配置、系统管理；保持旧路径可用 | 用户能从任务到问题、比较和报告连续导航 |
| 字号 | 正文/表格以 13–14px 为主，辅助内容尽量不低于 12px；标题与局部容器匹配 | 实测关键桌面视口，无重叠和重要信息裁切 |
| 可读性 | 提高灰字对比；正常文本以 4.5:1 作为设计验收目标；状态同时有文字 | 测量实际文本/背景颜色，检查错误、禁用和焦点状态 |
| 信息密度 | 缩减重复英文装饰标题、顶部留白和范围说明；结论/列表/主操作前置 | 工作台首屏可识别范围和风险，异常页首屏可处理任务 |
| 交互控件 | 图标操作有可访问名称和 tooltip；批量栏按选择状态显示；加载、空态、错误分开 | 键盘可操作关键路径，焦点可见，不单靠颜色表达 |
| 响应布局 | 验证 1366×768、1920×1080、390px 宽及 200% 缩放 | 可读可操作；大表格在容器内横滚，页面整体不异常溢出 |
| 术语 | 首层使用中文业务名称，技术 ID 和原始 JSON 放详情；单位和日期格式统一 | 用户不依赖 IssueScope、Trial 等内部词才能完成主流程 |

浅色/跟随系统主题属于 P2，不阻塞本轮。上述为待验收要求，不代表现有版本已完成无障碍认证。

## 6. 开发实施边界与参考模块

## 7. 测试与交付清单

每个任务提交时提供以下信息：

- 需求编号、实现范围、受影响页面/API、迁移或配置说明。
- 正常、空数据、加载、失败、权限不足及历史数据场景的验证结果；测试规模与改动风险匹配。
- 前端改动提供关键桌面/窄屏截图；后端提供关键合同、越权和边界测试结果。
- 明确完成、部分完成、待外部资源验收，不将模拟测试标成真实业务验收。
- 部署或认证配置变化时更新启动、升级和回滚说明，列出兼容性影响。

上线前至少覆盖：跨页搜索、执行完成但质量失败、单样本性能展示、全未知/部分证据、相同标签的多个比较、旧版本后运行、切换项目、批量冲突、网络重试、历史报告、项目越权和脱敏。业务故障/恢复用例按 AE-004 单独留存证据。

建议用户验收目标：5 名目标用户中至少 4 名，在测试地址、凭据和参考用例齐备后，不由开发者代操作，15 分钟内完成首次有效评测；给定一个失败用例，3 分钟内定位失败断言、预期/实际与来源 Trace。以上是本轮目标，尚未实测。
