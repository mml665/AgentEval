# AgentEval 0.14 团队自动化与质量趋势

## GitHub Actions 发布门禁

在仓库配置变量 `AGENTEVAL_URL` 为运行器可访问的 HTTPS 部署地址。在 Secret `AGENTEVAL_CI_TOKEN` 中配置仅对目标项目开放、权限为 `evaluate` 的机器令牌。打开 Actions 中的 **Agent release gate**，填写项目、候选 Agent 版本、Benchmark 版本、评分方案版本、基线评分批次。也可以在本仓库的发布工作流中调用 `./.github/workflows/agent-release-gate.yml`，通过 `needs` 让下游发布等待门禁成功。

同一个 GitHub Actions 运行的重跑使用同一请求键。工作流等待候选运行和初始评分批次完成，随后比对固定批次，检查候选版本范围内的开放阻断项、评分证据以及两个批次的当前有效性。已有基线若来自旧引擎，先在当前版本下重评，并使用新基线批次 ID。若启用了新的 Judge 计价策略，需要创建采用相同冻结策略的基线与候选运行。

```bash
python -m scripts.ci_gate --project-id "$PROJECT_ID" \
  --agent-version-id "$AGENT_VERSION_ID" --benchmark-version-id "$BENCHMARK_VERSION_ID" \
  --profile-version-id "$PROFILE_VERSION_ID" --baseline-batch-id "$BASELINE_BATCH_ID" \
  --request-key "$REQUEST_KEY" --report agenteval-gate.json
```

从仓库根目录执行。脚本从环境读取部署地址和令牌，支持本机 HTTP 测试。用相同请求键和参数重试。退出码 `0` 表示可发布，`1` 表示阻断，`2` 表示证据不足，`3` 表示配置、接口或通信异常。报告包含固定批次 ID、原因和阻断 Issue ID，GitHub Actions 将其上传为工件。门禁给出评测决策，实际发布由下游工作流或人工审批执行。

## 站内通知

当前项目的通知汇总升级后的评分完成事件和已记录的缺陷事件。每条任务通知打开对应的固定评分批次，缺陷通知打开原记录。首屏每 20 秒刷新。已读位置按项目与成员保存在浏览器，兼容部署 Token 共享该浏览器的读取位置。

## Judge 金额预算

在 API 和 Worker 环境配置输入、输出单价。单位为 **微美元／百万 Token**。例如每百万输入 Token 收费 1 美元，对应 `AGENTEVAL_JUDGE_INPUT_MICRO_USD_PER_MILLION=1000000`。两项单价均设置后启用估算，`AGENTEVAL_JUDGE_MAX_MICRO_USD` 大于零时开启每个 Run 的金额门禁，零表示仅计量。原有次数上限仍生效。

每个 Run 冻结单价、预算及预留规则，重试和重评共用同一额度。派发前按 `AGENTEVAL_JUDGE_RESERVE_INPUT_TOKENS` 与最大输出 Token 预留，启用金额门禁时，序列化请求字节数必须落在配置的输入预留上限内。收到合法用量后按报告的输入与输出 Token 结算估算费用。中断或缺少用量时保留预留额，防止提前释放额度。任务详情展示估算费用、预留、未计价调用和剩余额度。

此金额是基于供应商报告用量和配置单价的估算。供应商分词、附加费用或返回超过预留的实际用量均可能导致估算与账单差异。预算覆盖平台发起的 Judge 调用。历史未计价运行显示未计价调用数。

## 质量趋势、标签覆盖与主题

趋势固定 Agent 版本、Benchmark 版本和评分方案版本，支持最近 7、30、90 或 365 天。以 UTC 运行创建日期分组，使用已完成的初始评分批次。成功率分母为已判定试验，判定覆盖率分母为计划试验。未判定和排除的试验继续计入计划量，无样本的比例显示为空。

业务标签覆盖以固定 Benchmark 版本中的标签用例总数为分母，以时间窗口内至少有一次通过或失败判定的去重用例为分子。多标签用例会分别计入其标签。

在登录页或侧栏选择深色、浅色或跟随系统，选择保存在当前浏览器。旧部署首次打开保持深色。

## 验收范围

使用隔离数据库与本地 Agent 及 Judge 协议样例验证门禁三态、请求复用、费用预留、趋势分母、通知和主题。生产 Actions 端到端运行需要部署地址与目标项目机器凭据。真实双 Agent、Judge 人工校准及生产运行数据仍需实际业务资源。
